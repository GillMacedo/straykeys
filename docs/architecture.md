# Architecture

straykeys is one Go program in `cmd/straykeys`. Its only dependency is gopkg.in/yaml.v3, vendored, so the installed plugin (the whole repository) builds with `go build` and no network.

## Flow

1. **Configs (`config.go`).** `loadConfigs` reads each file, or stdin. `sniff` refuses empty, binary, non-UTF-8 and HTML text. JSON (a `.json` name) must pass `json.Valid`, so a cut or extended file is refused. YAML is parsed with yaml.v3 into `yaml.Node` trees, which keep line numbers, anchors and tags; every document is kept, so a second one can be reported. With `--configmap-key`, each ConfigMap's `data` value is parsed as its own config, and lines of a literal block (`|`) map back to the manifest. `--at` moves to a nested section.
2. **The struct (`load.go`).** `loadType` runs `go list -deps -json -- PATTERN` in `--dir` with `GOPROXY=off`, then type-checks the target package and its dependencies from source with `go/types`, skipping function bodies (`IgnoreFuncBodies`). Each package uses its own `ImportMap`, so vendored modules resolve. Type errors in the target package refuse the run; an unresolved type the schema needs refuses it too.
3. **Schema (`schema.go`).** `buildSchema` turns the type into a tree of `Shape`s for the chosen decoder: structs with their accepted keys, maps, lists, scalars with their kind, `time.Duration`, `any`, and opaque values. The field rules follow each library's source: `getStructInfo` in yaml.v3 (`yamlFields`), `typeFields` in encoding/json (`jsonFields`, with depth and tag dominance), and `decodeStructFromMap` in mapstructure v2 for viper and koanf (`mapstructureFields`). Types with `UnmarshalYAML`, `UnmarshalJSON` or `UnmarshalText` are opaque, unless `decodesPlainCopy` finds the `type plain T` pattern. `detectDecoder` picks the decoder from tag counts. For viper, `viperkeys.go` adds keys read with `viper.Get*` calls in the module.
4. **Check (`check.go`).** `checker.walk` follows the config and the schema together. For a struct, each key is matched exactly and then, for decoders that do so, case-insensitively; viper keys with dots are split. A key that matches nothing is `unknown-key`, with a hint from `nearKey` (separators and case ignored, then edit distance) or `elsewhere` (the same key below this struct, then anywhere). Scalars are checked by `scalarProblem` with each decoder's conversion rules, including sigs.k8s.io/yaml's YAML-to-JSON conversion, which uses the target type except below promoted fields. Merge keys (`<<`) and aliases are expanded, with cycle detection. If no top-level key belongs to the struct, the file is refused as another file.
5. **Report (`main.go`).** Text or JSON. Exit 0, 1 (findings, unless `--fail-on never`) or 2 (refused, with nothing on stdout).

## How the rules are kept honest

`tests/decoders` is a separate module that imports the real libraries. It mutates fixture configs (renamed, recased, moved and added keys, values of other types), runs straykeys on all of them in one call, and for every scalar in every config checks that straykeys reports the key exactly when changing the value doesn't change the decoded struct. It also checks that straykeys reports a load error exactly when the library returns one. Every rule in `schema.go` and `check.go` that is about a library's behavior is covered by a suite there.
